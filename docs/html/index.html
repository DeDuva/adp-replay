ADP-REPLAY · EVIDENCE-GATED MODEL COMPARISON

Everyone has a number.
Nobody can check one.

Every claim that one model writes better code than another is produced by the party that benefits from it, scored by a grader it controls, on a corpus it selected, through a harness it wrote — and published as a number, not as an artifact anyone can re-derive. When the gap is five points, five things moved at once and no mechanism exists to say which one moved the result.

adp-replay records agent trajectories on closed-world coding tasks and replays them under a substituted model with the harness pinned, on evidence it does not grade itself — hash-chained into ADP, signed there, and verified through an endpoint that answers to somebody else. Its most load-bearing feature is the set of comparisons it refuses to make.

01 · WHY

A leaderboard is not a measurement

Agentic coding evaluation has a shape that would not survive in any other field that uses the word evidence. A model is run against a task suite by a scaffold its own vendor wrote, graded by a checker that vendor configured, on tasks that vendor picked, and the result is published as a percentage with no artifact behind it. Nothing is hidden, exactly — there is simply nothing to hand over. The run left no record that anyone else could re-derive the number from.

That would still be tolerable if the model were the only thing that varied. It never is. An agentic result is the joint product of five factors, and a comparison is only attributable to the model when the other four are held identical. Toggle them below.

Two further problems sit underneath the first, and neither is solved by publishing more numbers. Reproducibility: a coding task that reaches the network, waits on a background process, or reads the clock produces a different run six weeks later for reasons that have nothing to do with the model — so a corpus that was never audited for closure cannot support a claim about anything. Statistical honesty: agent runs are stochastic, so the same model on the same task passes sometimes and fails sometimes; with repetitions in play, the unit of independent evidence is the task, and treating trajectories as independent samples manufactures confidence out of correlation. These are not exotic failure modes. They are the default.

02 · THE CLEAN COMPARISON

Fork at zero — and the fork that is not a comparison

There is exactly one way to hold the other four factors identical: don't re-run the experiment, replay it. Record what an agent actually did on a task — every model call, tool execution, and filesystem delta — then materialize the same base state, reconstruct the same initial context, pin the same harness and the same scorer, and substitute only the model. That is fork-at-zero, and it is a model comparison and may be described as one.

Recording also makes a second, tempting thing possible: resume a recorded trajectory from step k under a different model and see whether it finishes. That is fork-at-step, and it is not a model comparison. It measures how well model B continues model A's policy prefix — a genuinely useful diagnostic, and a completely different question. Almost every intuitive way of reading it out loud turns it back into a comparison, which is why this repository does not rely on discipline to keep the two apart. It attaches a banner that no configuration can remove. Try it.

WHAT REPLAY BUYS
The paired design. Both arms answer the same task from the same bytes, so the comparison is per-task and paired — which is what makes an exact McNemar test the right instrument and a small corpus sufficient. Re-running two models against a suite independently throws that pairing away.
WHAT REPLAY DOES NOT BUY
A recorded filesystem is not a recorded world. v0 captures the filesystem and nothing else — no processes, no sockets, no kernel state — and state_completeness is a required field on every manifest, reprinted in the header of every report, precisely so this limit cannot be lost between the run and the write-up.
03 · DEFENSIBILITY

Commitments made before the data

Replay makes the comparison clean. It does not, by itself, make the answer defensible — a clean comparison run enough times, sliced enough ways, with the bar set afterwards, produces exactly the result you were hoping for. Everything below was therefore fixed before the measurement it governs existed, and each is enforced by code that fails rather than by a paragraph asking people to be careful. Expand any of them.

The number of tasks is the single easiest place to launder a result: too few and the study cannot detect the effect it claims to have found; chosen after the fact and it is not a study at all. So the corpus size comes out of a simulation, before Task 1.3 goes looking for tasks — 170 tasks × 3 repetitions, power 0.806, which is 1,020 recorded trajectories across both arms. Cheaper designs reached the same power for fewer trajectories and were still rejected: 310 tasks at one repetition each hits 0.812 for 620 trajectories, but within-task variance is not defined at a single repetition, and the analysis has already committed to reporting it. A design cannot be recommended on cost when it cannot support the analysis it exists to feed.

A design that only holds at one assumed effect size is a number, not a result — so the sensitivity curve is published with it. Drag it.

Two things this figure is honest about. Every input to it — base success rate 0.45, between-task SD 1.5 on the logit scale, alpha 0.05 — is a guess until pilot data replaces it, and the published analysis says so in those words. And power rises with between-task spread rather than falling, which reads backwards until you notice that a wider spread of task difficulty needs a larger shift on the log-odds scale to move the marginal rate by the same ten points, and a larger shift produces more discordant pairs — the only pairs McNemar reads. The design is not at risk from a corpus more heterogeneous than assumed. It is at risk from a smaller true effect, which is what the slider shows.

A trajectory recorded against one provider's wire format has to be translated to replay against another. Whatever the translation drops, the substituted model never sees — and if enough is dropped, the observed difference is evidence about the translator rather than about the models. That does not make the result weak; it makes it uninterpretable, which is why G0 is a hard stop: median context fidelity ≥ 0.85 per provider pair, or replayer work stops.

The metric, its element vocabulary, its weights, and the 0.85 bar were all committed to the repository before any code that scores against them existed — with a machine-readable transcription that a test compares against the published prose, so the probe cannot quietly score against different numbers than the ones on the page. Three design choices carry most of the weight. Scoring runs per element type, then across types, because message text outnumbers everything else by two orders of magnitude and an instance-weighted score would read near 1.0 while every tool definition was being dropped. A transformed element scores exactly 0.5, fixed in advance, because there was no evidence available before measurement about whether content or frame matters more, and a neutral split is the only one that cannot later be argued into place. And classification follows the consequence, not the mechanism: if losing a weight-1 reasoning signature forces its weight-2 reasoning trace to be dropped, the trace scores as lost.

The first reading failed — one cell of twelve at 0.846 against a 0.85 bar. Amendment 1 corrected the rule responsible, and because an amended metric that only ever showed its post-amendment numbers would be unfalsifiable, every G0 report prints both columns side by side, forever. The gate now passes at 0.951 on the worst in-scope cell. It is also labelled honestly: the reading is round_trip_only — it says what this repository's translators preserve, not what the target providers accept, and the registered grounding check has not run.

A task is closed when running it twice, on two machines, at two different times, can differ only because the model differed. Three things break that, and the audit flags all three. What makes the audit useful rather than a machine for rejecting everything is that it cares when a hazard fires.

Network at build time is fine: the environment is pinned by image digest, so whatever the build fetched is already inside the artifact every replay starts from. Network at run time is not, because it puts a third party's availability inside the measurement and a replay six weeks later gets a different internet. A clock read in a solution is fine — it produces a different trajectory, which is a thing the experiment measures. A clock read in a test is blocking, because it produces a different verdict for the same trajectory, which is the thing that makes a result uninterpretable.

Two restraints keep the audit from becoming noise, because an audit that over-matches gets ignored and an ignored audit is worse than none — it makes the corpus look examined. Commented-out lines are skipped, since flagging a commented-out curl trains people to ignore the tool. Loopback URLs are not network use, since a task talking to something it started inside its own container is closed. Every finding carries the file, the line, the matched text, the pattern that matched it, and why it matters — enough to check by hand and to disagree with.

A flagged task is not a broken task. It is a task this experiment cannot interpret, which is why the corpus file records the rejected tasks alongside the accepted ones, with their findings: a corpus that listed only what survived would hide its own selection, and the interesting question about a closed corpus is always what had to be thrown away.

With 170 tasks at 3 repetitions there are 510 trajectories per arm, and a bootstrap that resamples those 510 will produce a tighter interval and a smaller p-value than one that resamples the 170 tasks. It is also wrong. Three repetitions of one task are three looks at the same question, not three independent samples; treating them as independent asserts information the experiment never collected. In the limiting case where repetitions within a task agree perfectly, the interval narrows by a factor of about √3 — the same data, made to look 1.7× more certain, with no new evidence anywhere.

So the resampling unit is fixed to tasks, appears in the report JSON as a field, and is on the never-cut list in the execution plan. Click the toggle to see the shape of the claim each choice is making.

The same discipline governs the rest of the analysis. The paired test is an exact McNemar, chosen before data collection rather than after seeing which test was kinder. ICC and a between-versus-within variance decomposition are reported alongside it — near 1, the corpus is doing the work and more repetitions buy little; near 0, the outcome is mostly run-to-run noise and no number of such tasks settles anything. When there are too few repetitions to separate the two components, the field reads unavailable with a reason, because reporting zero would read as "no within-task variance" instead of "not measured".

An instrumentation layer that costs a third of the run is an instrumentation layer people switch off for the runs that matter. So overhead is a gate, not a footnote: median recording overhead ≤ 10%, inclusive of ADP round-trips — the real system, not the recorder measured in isolation. It reads 1.4%.

Overhead is the recorder's cost divided by how long a step takes, so a single percentage means nothing without the step duration beside it; the curve is what says whether the headline is robust or an artifact of one choice. It stays under budget at every step duration measured, and the transferable number is the absolute one: roughly a millisecond of wall clock per recorded step, against a local ADP.

Two details make the measurement mean what it says. The recorded arm closes inside the measurement window — the final flush is counted, because a recorder that abandoned its tail would look fast by not doing its job. And both arms simulate the step itself with a sleep, which is the honest way to isolate the recorder's cost: a real model call adds seconds of variance that swamp the thing being measured and turns the result into a fact about provider latency. What this does not establish is stated in the report rather than left to be discovered — 40 steps against a warm database on one machine is not a corpus, and a remote ADP with 50ms of latency has not been measured.

The property underneath the number is that a tool call never blocks on an ADP write. Events spool locally and flush asynchronously in batches with a producer sequence; a contiguity rejection replays the spool from the sequence ADP names; the spool trims at the high-water mark ADP returns. The done-condition was not "it is fast" but "kill it mid-run and the chain is still gap-free" — checked with a real SIGKILL against a live ADP, and confirmed by ADP's own completeness check rather than by this repository's opinion of itself.
04 · WHY ADP

Evidence you grade yourself is not evidence

Everything in §03 is a commitment this repository makes about its own conduct. Every one of them is worth exactly as much as the record they were applied to — and if that record lives in a log the same tool wrote, verified by a checker the same tool ships, then the whole apparatus reduces to trust me with more steps. A replay harness that also owned its evidence store would be certifying itself.

So it doesn't own one. Every recorded step is appended to ADP as a hash-chained session event, where each event commits to its predecessor and the chain head is what the signed artifacts carry. Snapshot bytes never leave the machine — they are attested by digest, and ADP returns a signed DSSE envelope binding the commit to that digest, so state provenance is attested without moving large payloads. A run closes against a final git sha, binding the trajectory digest to the code that was produced. The score is reported as an ordinary signed gate result carrying a spec_digest, so "the same eval, rerun" is checkable rather than asserted. And one call answers whether the whole thing holds up.

CHAINS_OK
The events ADP holds were not edited. Every event commits to its predecessor, so tampering anywhere breaks every hash after it — and the chain covers the typed columns, not just the opaque payload.
EMITTERS_OK
ADP was given all of them. A perfectly valid chain can still be missing an event that never arrived, so the emitter numbers its own events and a gap is reported rather than averaged away.
ENVELOPE + DIGEST
The signed attestation over the run still describes the run: the DSSE envelope verifies, and the trajectory digest it names matches the chains that exist now.
SEPARATELY_AUTHORIZED
The identity that reported the score is not the identity that opened the run. False means the run scored its own work — a self-report, which ADP refuses to let look like anything else.

That last one is the hinge, and it is checked at the start of an experiment rather than at analysis time — a preflight opens a throwaway run, reports a throwaway eval, and reads ADP's own answer back. Discovering that every score was self-reported after the corpus is burned and the budget is spent is not a finding, it is a loss. Two different tokens are not two different principals, so the check asks the server, not the config file.

A WIRE CONTRACT, NOT A LIBRARY
adp-replay depends on ADP over REST as a versioned contract. It links no ADP library and assumes nothing about ADP's implementation language; the client is generated from ADP's OpenAPI spec, CI fails while the generated code is stale, and the served ADP-API-Version is asserted at startup — which works because ADP serves that header on every response, including 401s, so the assertion runs before this client holds a token. A version mismatch fails loudly at the start, never mid-experiment.
AND THE CONTRACT IS TESTED, NOT ASSUMED
Requests are typed by the spec; responses are not, because ADP documents them in prose. So a generated client can only ever type half the contract, and the untyped half is where a consumer's bugs live — which is why contract tests run against a live ADP rather than a mock. They found three real discrepancies, published as findings rather than quietly worked around, each with a test that will fail loudly when ADP fixes it.6
05 · WHY NEUTRAL

The party that benefits cannot be the party that certifies

This is not a moral claim about anyone's conduct. It is what the word evidence means in every other field that has had to make it load-bearing. Drug trials pre-register their endpoints and are audited by someone who does not sell the drug. Financial statements are signed by an auditor who is not the CFO. Safety cases are assessed by a regulator with no revenue attached to the answer. None of that machinery exists because the people involved were dishonest; it exists because the incentive gradient is real and the results are otherwise uncheckable, and everyone concerned would rather be believed than merely sincere.

Agentic coding evaluation has none of it. The lab that trains the model also writes the harness that runs it, owns the trajectory log the harness keeps, chooses the corpus, configures the grader, and publishes the number. That is not four safeguards failing — it is one entity occupying all four positions, so there is no second position from which the first could be checked. And the closer agent evaluation gets to procurement decisions, safety arguments, and regulatory filings, the less that arrangement will survive contact with anyone whose job is to ask for proof.

WHY NOT A LAB'S OWN NUMBER

Not because it is false — most of them are honestly produced. Because it is unfalsifiable. There is no artifact to disagree with: no recorded trajectory, no attested initial state, no scorer digest, no way for a third party to re-derive the figure or to demonstrate it wrong. A claim that cannot be checked is not a strong claim that happens to lack support; it is a different kind of object. And when the harness that would have to produce the record is the same product being evaluated, "just publish the logs" asks the interested party to grade its own homework in more detail.

WHY NOT ANOTHER LEADERBOARD

A neutral benchmark org just relocates the trust: now everyone trusts that body's corpus, harness, and grader, and the same four positions are occupied by one entity with different letterhead. Benchmarks also decay — they leak into training data, get targeted, and quietly stop measuring what they were built for. What is missing is not a better-owned scoreboard. It is portable, verifiable evidence: a record shaped so that anyone's claim becomes checkable, including this project's. adp-replay publishes an instrument, not a ranking.

WHY NOT THE HARNESS'S OWN LOG

Every harness already records something — session JSON, shadow repositories, checkpoint files — in a private format, invisible to the repository and incompatible with every other harness. Three harnesses produce three incomplete audit trails and no cross-harness comparison at all. Worse, a log the harness can rewrite is not tamper-evident, and one nobody outside can verify is decoration. ADP's contribution is exactly this: a hash-chained, signed, third-party-verifiable record with one endpoint that says whether it holds up — falsifiable by any holder of a read token.

Neutrality here is a set of mechanical properties, not a posture. No provider is special-cased — three providers, a symmetric pair matrix, and the fidelity gate applied identically in both directions of every pair; a narrowing of provider scope is an option the gate offers explicitly rather than a quiet exclusion. No provider is called anywhere in the package — the agent is an injected protocol, so nothing about a vendor's API is baked into the instrument. The scorer must be a different principal than the runner, asserted before spend, or the experiment does not start. The evidence store is somebody else's, reached over a versioned wire contract with no linked library. And everything is re-derivable: the manifest digest is computed over the canonical form with the run id excluded, so a published manifest verifies from the file alone, on a machine that has never heard of where it was stored.

Apache-2.0, both projects. The point of doing it this way is that the result does not depend on anyone's opinion of the people who produced it — including ours.

06 · REFUSALS

What it will not say, and where that is enforced

The characteristic failure of an evaluation system is not a wrong number. It is a number that should never have been produced — a comparison across two different scorers, a diagnostic quoted as a comparison, a corpus quietly smaller than the design called for, an unverifiable run counted as a pass. Each of those is a small, reasonable-seeming step taken under deadline pressure, and each is invisible in the published artifact.

So they are foreclosed in code rather than in a style guide. Every refusal below has a test that fails if the refusal stops working; each one gives up something real, which is why it is listed with what it costs.

The corpus builder takes its target from the power analysis and will not emit a corpus file that falls short of it. The obvious shortcut — run the auditor over whatever tasks are lying around, ship the file, describe the shortfall in a footnote nobody reads — is unavailable, because the file itself does not get written. What it costs: right now, the corpus. Terminal Bench is not installable in this build environment, so tb2_closed_corpus.json does not exist and Task 1.3's done-condition is not met — which is exactly the outcome this refusal is for. The gap is visible instead of papered over.

Scorer identity is ADP's spec_digest on the eval. Two results produced by different scorers are not comparable, and combining them is how an eval-gated comparison lands the wrong winner while every individual number is correct. A deliberate digest mismatch errors out rather than aggregating. What it costs: a mid-experiment scorer fix invalidates the arm rather than silently splicing two regimes together — you re-run, or you report two experiments.

Starting a run with a single shared token fails immediately with a clear message. The check runs before the first model call, not at analysis time — a corpus scored entirely by its own runner is not salvageable after the fact, and finding out later costs the whole budget. What it costs: operational friction. Two principals must be provisioned before anything runs, which is precisely the friction that makes the resulting separately_authorized mean something.

Every fork-at-step artifact, report, and console run carries the banner verbatim, and it cannot be suppressed by configuration because it is derived from the run's mode rather than stored as a field someone could set to false. The report schema goes further: the is_model_comparison flag is true only when every result in the document is fork-at-zero. What it costs: the most quotable finding this instrument can produce is permanently harder to quote — which is the point, because it is the one most likely to be repeated without its caveat.

A pass and a fail are both claims about the model. A run whose evidence does not stand up supports neither, so it becomes error, with the failing sub-check recorded so the downgrade is diagnosable rather than merely observed. Errors then count against the majority when deciding whether a task was solved — one pass and four unverifiable attempts does not report as solved. Verified by tampering with a stored event and watching the verdict change. What it costs: a flaky recorder shows up as a worse-looking model rather than as a smaller sample, which is the conservative direction and the uncomfortable one.

The registered metric has two halves: a round-trip through this repository's translators, and a grounding check that the rendered request is actually accepted by the target provider's API. Only the first has run, and the report says round_trip_only in its header rather than reporting a number that reads as more than it is. Likewise, an amended metric prints its pre-amendment numbers beside the current ones in every report, permanently, so the correction stays checkable by someone who did not watch it happen. What it costs: the gate's headline is weaker than the figure would allow — G0 passes at 0.951, with a label saying what that 0.951 is not.

State completeness and median context fidelity come before the statistics — in the HTML and in the JSON, where the ordering of the top-level keys is specified as part of the schema. Both are limits on what the numbers mean, and a limit that appears after the conclusion has already been read is not a limit. A consumer that reads only the head of the document still gets them. The same rule governs the write-up: the state-completeness specification is reprinted verbatim in the limitations section. And null fidelity means not measured, which the schema distinguishes from zero. What it costs: every report opens by telling you what it cannot tell you.
07 · WHERE IT STANDS

Built, gated, and not yet run

Phases 0 through 3 are implemented and merged, against a live ADP serving contract 0.1.0. Both gates pass: G0 at 0.951 median fidelity on the worst in-scope cell, G1 at 1.4% recording overhead against a 10% budget. Working end to end: the self-certifying manifest and its digest; the content-addressed store and reproducible filesystem capture, attested to ADP by digest with the bytes never leaving the machine; the recorder and its spool, which survives a real SIGKILL and resumes into a gap-free chain; fork-at-zero, the fork-at-step diagnostic, and the runner's identity preflight; exact McNemar, bootstrap intervals over tasks, ICC and variance decomposition; self-contained HTML and JSON reports; and evidence gating, checked by actually tampering with a stored event.

Three things are not done, each blocked on a dependency unavailable in the build environment, and each enforced as unfinished in code rather than merely noted. The corpus: the closure auditor is complete, but Terminal Bench is not installable here, so the corpus file does not exist and the builder refuses to write a short one. Any real model call: no provider is contacted anywhere in the package — the agent is an injected protocol, and running the experiment is Phase 4 work needing keys and budget. The Inspect binding: inspect-ai could not be installed, so the wrapper is verified against a fake solver of the same shape and says so in its own docstring.

The target state is one artifact: the full experiment at the scale the power analysis recommends, across providers, with every manifest and every report published alongside a write-up that leads with fork-at-zero — the state-completeness specification reprinted verbatim in its limitations, and any fork-at-step result carrying its banner. The instrument is finished. The measurement is not, and this page does not claim otherwise.
